# R29: UI audit before the Gdansk device test (gdansk-audit-1)

Branch `gdansk-audit-1`, off `main` at 1c903fb (v1.2). Read-only audit: this file is the only change. No code, schema, RLS, RPC, migration or dependency change; no database call, no `activate_event`, nothing pushed or merged.

## Method

- Read `CLAUDE.md`, `11_PHASE_GDANSK.md`, `12_ACCEPTANCE_TESTS.md`, R15 to R28, all of `src/index.css`, every page and component in `src`, and the hooks behind loading and error states (`useOrders`, `useDesigns`).
- Contrast was computed with the WCAG relative-luminance formula for every token pair the code actually renders, including alpha blends (opacity, `color-mix` tints) flattened onto the surface they sit on. The script lived in the session scratchpad and is not committed.
- Widths 360, 390 and 430 px were reasoned from CSS: `.content` pads 20 px a side and `.card` 16 px, so a card's inner width is 288, 318 and 358 px.
- **Nothing was run in a browser or on a device.** Where a finding depends on font metrics or engine behaviour it says "estimated" or "device check".

Severity: **P0** must fix before the event, **P1** should fix this week, **P2** after the event. Effort: S under an hour, M a few hours, L a day or more. Scope: **CSS/markup** means class, style or JSX structure only. **Logic** means it also changes state, a hook's return value or a handler.
