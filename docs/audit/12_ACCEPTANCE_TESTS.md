## A. Админка: настройка события

### A1. Создание события
Как админ, я хочу создать событие с названием, местом и датами, чтобы кассы и пресс работали внутри него.

Критерии:
- AC0: список «Events · N» сверху, форма скрыта за кнопкой «New event» (у той же строки). Кнопка меняется на «Close», форма закрывается и после успешного создания.
- AC1: поле «Event name» обязательно, кнопка «Create event» неактивна при пустом имени.
- AC2: «Location», «Start date (optional)» и «End date (optional)» необязательны.
- AC3: после создания событие появляется в списке «Events · N», по умолчанию не активное.
- AC4: событие допускает диапазон дат (10 и 11 октября). Поле «End date (optional)» неактивно, пока не задана «Start date (optional)», и не позволяет выбрать дату раньше старта.
- AC4a: если конец раньше начала, сообщение «End date must be on or after the start date.» Сброс начала сбрасывает и конец.
- AC4b: в карточке события диапазон показан как «10–11 Oct 2026», одна дата как «10 Oct 2026».
- AC5: форма не ломает раскладку на узком экране (iPhone 13), после выбора даты поля остаются в ширину экрана.

### A3. Активация события
Как админ, я хочу активировать одно событие, чтобы на всех станциях работа шла именно в нём.

Критерии:
- AC1: активным может быть только одно событие, активация другого снимает прежнее.
- AC2: название активного события видно в шапке.
- AC3: без активного события кассир и пресс видят «No active event. Ask an admin to activate one.».
- AC4: станции подхватывают смену события без ручной перезагрузки за 20 до 30 с.

### A4. Дизайны
Как админ, я хочу загружать макеты с фото лицевой и обратной стороны, чтобы пресс печатал правильное.

Критерии:
- AC0: карточка макета показывает обе фото рядом с подписями «Front» и «Back» (нет фото: плитка с инициалами). Тап по фото открывает его на весь экран, тап закрывает. Под карточкой один ряд из трёх одинаковых кнопок «Edit», «Hide»/«Show», «Delete». «Replace front» и «Replace back» стоят под своей фото. Выбора Big/Small нет ни в форме, ни в карточке.
- AC1: макет создаётся с названием, совместимыми цветами и фото сторон.
- AC2: фото больше 5 МБ сжимается автоматически («Preparing photo…», «Uploading…»), загрузка не падает.
- AC3: «Edit» меняет название, цвета и фото.
- AC4: «Hide» скрывает макет от касс, «Show» возвращает. Скрытие, а не удаление.
- AC5: «Delete» для макета, по которому есть заказы, запрещён: «This design is used by orders. Hide it instead.»
- AC6: пустое имя: «Enter a design name.»
- AC7: изменения макетов доходят до станций после перезагрузки страницы (известное ограничение, не блокер).
- AC8: вкладка «Compatibility» (пятая в Admin) показывает матрицу: строки это все макеты события, включая скрытые (серые, с меткой «Hidden»), столбцы это цвета события. Пустой список `compatible_colors` читается как «все отмечены». Если отмечены все цвета, в базе пустой список (новый цвет события разрешается сам), иначе только отмеченные ключи в порядке палитры. Ноль отмеченных нельзя: последний цвет не снимается, показывается подсказка «At least one colour must stay ticked.» Список, где нет ни одного цвета палитры, показывается без отметок и с пометкой «⚠ No colour of this event matches» (касса для такого списка показывает все цвета).

## C. Касса

### C1. Создание заказа
Как кассир, я хочу быстро собрать заказ из цвета, размера и принтов, чтобы отправить его на пресс.

Критерии:
- AC1: цвет и размер обязательны, принты и имя клиента нет. Печать выбирается в одном из двух режимов: «Bundle» (по умолчанию) или «Custom print». Порядок полей формы: Print, затем Shirt color, затем Size, затем Client name (список цветов зависит от выбранной печати, поэтому печать идёт первой).
- AC2: «Send to press →» неактивна, пока не выбраны цвет и размер.
- AC3: «Bundle»: один макет на обе стороны (front и back сразу), цвета, не совместимые с выбранным макетом, СКРЫТЫ из списка. Если выбранный цвет стал несовместим, он сбрасывается в «не выбран». Есть выбор «No print». «Custom print»: отдельные списки Front и Back, цвета, не совместимые с выбранными макетами, затемнены (подсказка «not recommended for the selected print (still allowed)»), но остаются доступными для выбора. Пустой список совместимых цветов у макета разрешает все цвета (подстановочный знак: он не сужает пересечение с другим макетом). Если ни один цвет события не подходит макету, показываются все цвета без затемнения.
- AC3a: заказ из «Bundle» хранит один и тот же макет в `design_front_id` и `design_back_id` (новой сущности и миграции нет). Переключение режима очищает выбор печати и сохраняет цвет, размер и имя клиента.
- AC4: после отправки видно «Sent to press — Order #N», форма очищается.
- AC4a: выбранная печать сворачивается. «Bundle»: после выбора макета (или «No print») сетка плиток и большое превью заменяются одной строкой: маленькие фото front и back (тап открывает крупный просмотр), имя макета и кнопка «Change», которая снова открывает сетку. «Custom print»: так же сворачивается каждая выбранная сторона отдельно (одно фото, имя или «None», «Change»). Макет, скрытый после выбора, строку не показывает, сетка остаётся открытой.
- AC4b: «Reset» (серая, без жёлтого, высота 56 px против 72 px у «Send to press →») стоит слева от «Send to press →» (в нижней панели на телефоне и в конце карточки от 900 px). Активна только когда что-то выбрано или введено, неактивна пока идёт отправка. Очищает печать, цвет, размер, имя клиента, строку про сброшенный цвет и ключ повтора черновика так же, как успешная отправка. Режим («Bundle» или «Custom print») не меняет. Без окна подтверждения.
- AC3b: «Bundle»: если выбор макета сбросил уже выбранный цвет, под рядом цветов остаётся строка «Colour cleared: not available for <имя макета>» (оранжевая), пока не выбран цвет, не выбран другой макет, не переключён режим или не отправлен заказ. «Custom print»: если хоть один цвет не рекомендован для этой печати, он показан полным цветом с пунктирной оранжевой рамкой и штриховкой (не бледнеет), у него `aria-label` «<цвет>, not recommended for this print», а под рядом цветов видна строка «Hatched colors are not recommended for this print (still allowed)» (подсказка-tooltip остаётся, но не единственная, на касании её не видно). Выбранный цвет: «✓ » перед названием и кольцо с тёмным зазором.
- AC5: на телефоне (уже 900 px) вверху две вкладки «New order» и «Queue», по умолчанию «New order». Кнопка «Send to press →» лежит в нижней липкой панели вместе с одной строкой-сводкой (например «Black · M · Front: Name · Back: Name», только выбранные части), клавиатура не закрывает кнопку. В режиме «Bundle» макет в сводке один раз («Black · M · Bundle: Name»). Слева от «Send to press →» компактная нейтральная «Reset» (серый текст, 56 px при 72 px у «Send to press →», по центру строки). На широком экране вкладок нет.
- AC5a: пока не выбраны цвет и размер, под кнопкой серая подсказка: «Pick a color and a size», «Pick a color» или «Pick a size».
- AC5b: переключение на «Queue» и обратно не стирает черновик (цвет, размер, макеты, имя).
- AC6: заказ получает следующий номер события, нумерация без дублей.
- AC7: список макетов читается с состояниями. Пока читает: над плитками Print «Loading designs…». Ошибка чтения: «Couldn't load designs. Check the connection.» и кнопка «Retry» (72 px), которая повторяет чтение; ранее загруженные макеты при ошибке не пропадают. Плитка «No print» доступна всегда. Остальные страницы с макетами (Press, Stats, Admin) без изменений.

### C2. Повторная отправка при плохой сети
Как кассир, я хочу, чтобы при плохой сети повторное нажатие не создавало дубль.

- AC3: если черновик изменили после неподтверждённой отправки, сообщение «Order #N was already sent with the earlier details. Cancel it under In progress, then send again.»

### C3. Очередь кассы
Как кассир, я хочу видеть свои открытые заказы и готовые к выдаче, чтобы выдать футболку клиенту.

Критерии:
- AC1: «In progress · N» показывает мои открытые заказы.
- AC2: «Ready for pickup · N» показывает только готовые заказы, которые создал этот кассир (чужие готовые заказы и их кнопка «Cancel order» на кассе не видны). Секция «Ready for pickup» стоит выше «In progress». Это правило интерфейса: сервер не проверяет, кто отменяет или выдаёт заказ.
- AC2b: «In progress · N» тоже только мои заказы (New и In progress).
- AC3: «✓ Picked up #N» закрывает заказ, он пропадает из Ready. «Cancel order» у карточки Ready компактная, справа, с отступом сверху, не на всю ширину, высота от 44 px; у карточек In progress она прежняя, на всю ширину. Отмены после «Picked up» нет ни в интерфейсе, ни на сервере (решение D25 C: позже).
- AC4: «Cancel order» с подтверждением, из In progress и из Ready. Кнопка видна сразу: красная рамка и красный текст (цвета только из токенов), высота как у других кнопок. Окно подтверждения прежнее.
- AC5: звук и оверлей «Order #N ready» только для заказов, которые создал этот кассир.
- AC6: оверлей не повторяется после перезагрузки или реконнекта для уже показанных заказов.
- AC7: после возврата из блокировки или фона приходит один догоняющий алерт на пропущенные.
- AC8: на вкладке «Queue» (телефон) бейдж показывает число моих готовых заказов и скрыт при нуле.
- AC9: закрытие оверлея «Order #N ready» открывает вкладку «Queue».
- AC10: у заказа «In progress» в Queue кассы видно «Claimed by <имя>», как на прессе: той же строкой и тем же стилем, что «Sold by <имя>», имя жирным. Если имя не нашлось, отдельная строка «Claimed» того же стиля (не в строке «Sold by»).
- AC11: если пресс (или другой человек) отменил МОЙ заказ из New, In progress или Ready, на кассе, на обеих вкладках, появляется плашка «Order #N was cancelled by <имя>. Check with the press.» («the press», если имя не нашлось) с кнопкой «Dismiss», исчезает сама через 30 секунд. Без звука. Свою отмену и чужие заказы плашка не показывает. Только пока есть связь: если связь пропала, заказ просто исчезнет при обновлении без плашки.
- AC12: пока первая загрузка заказов не прошла, обе секции Queue показывают «Loading orders…», а не «None of your orders is ready yet.» и «No open orders from you.». После загрузки пустая секция показывает прежний текст.

## D. Пресс

### D1. Получение и работа с заказом
Как печатник, я хочу видеть новые заказы со звуком и взять заказ в работу, чтобы не печатать дубль.

Критерии:
- AC1: новый заказ появляется на прессе без перезагрузки со звуком.
- AC2: карточка показывает номер, цвет, размер, принты front и back (у заказа «Bundle» это фото front и фото back одного макета), имя клиента, время ожидания.
- AC3: «Claim — start printing» переводит заказ в работу, «✓ Ready» в готов.
- AC4: статусы идут только вперёд, повторное нажатие безвредно.
- AC5: порог ожидания подсвечивается на 10 минутах (оранжевый) и 15 минутах (красный, пульс). До `gdansk-ux-5` предупреждение было на 7 минутах.
- AC6: фото принтов достаточно крупные, чтобы отличить макеты: тап по миниатюре открывает крупный просмотр.
- AC7: «Cancel order» с подтверждением, заказ исчезает у кассира.
- AC8: карточка заказа: номер, статус, цвет, размер и имя клиента в одной шкале шрифтов (номер крупный, остальное один размер и вес), имя кассира мельче. У заказа «In progress» на прессе видно «Claimed by <имя>». Фото принтов на телефоне крупнее (около 120 px), тап по ним открывает крупный просмотр.
- AC9: если заказ, который пресс видит (New или In progress), отменил кто-то другой, на экране пресса появляется красная плашка «Order #N cancelled by <имя>» с кнопкой «Dismiss» (исчезает сама через 30 секунд, до `gdansk-ux-7` было 15). Без звука. Свою отмену плашка не показывает. Только пока есть связь: если связь пропала, заказ просто исчезнет при обновлении без плашки.
- AC10: пока первая загрузка заказов не прошла, пресс показывает «Loading orders…» в строке счётчика и в пустом состоянии, а не «0 in queue» и «Queue is empty 🎉». После загрузки: «N in queue» и «Queue is empty 🎉» как раньше.

## K. Известные ограничения (не блокеры)

- Кто может отменить или выдать заказ, сервер не проверяет (`set_order_status` не смотрит на вызывающего). Запрет чужих заказов на кассе и экран «Orders» только правила интерфейса. Закрывается RPC и RLS до Познани.
- Дизайны грузятся один раз на событие: Hide и Show доходят до станций после перезагрузки.
- PIN админа теряется при перезагрузке страницы по замыслу.
- Иконки PWA заглушки.
- Безопасность на уровне PIN и anon-ключа принята до Познани (20 до 22 ноября), там вводится настоящая авторизация.
- Веб-приложение не звонит при заблокированном экране. Вся защита это wake lock и правило Auto-Lock «Never» на смену.
- Составных ролей нет: одна роль на аккаунт. Klaudia (Press/Floor) работает в приложении как Press, Zuzanna S., Julia и Egor (Cashier/Floor) как Cashier.
- PIN у всех сотрудников `0000`, у админа свой. Безопасность на уровне PIN принята до Познани.
- Макеты (Hide и Show) обновляются на станциях после перезагрузки страницы: менять набор макетов нужно до открытия смены.

## N. SQL-шпаргалки (Supabase, SQL Editor)

Кто в базе:
```sql
select name, role, is_active from users order by role, name;
```

Деактивировать или вернуть человека:
```sql
update users set is_active = false where name in ('Имя1', 'Имя2');
update users set is_active = true  where name = 'Имя1';
```

Какое событие активно и его даты:
```sql
select id, name, is_active, event_date, event_end_date from events order by name;
```

Сводка по статусам в активном событии:
```sql
select status, count(*) from orders
where event_id = (select id from events where is_active)
group by status order by status;
```

Заказы, которые ждут Claim или в работе (для L4.1, самые старые сверху):
```sql
select event_order_no, status, cashier_name, new_at, in_progress_at
from orders
where event_id = (select id from events where is_active)
  and status in ('new', 'in_progress')
order by new_at;
```

Очистка заказов перед ивентом (H1.5), событие, макеты и персонал остаются:
```sql
delete from orders where event_id = (select id from events where is_active);
select count(*) from orders;
```

Следы автотестов, ждём нули:
```sql
select 'events' as t, count(*) from events where name like 'ZZ-%'
union all select 'designs', count(*) from designs where name like 'ZZ-%'
union all select 'users', count(*) from users where name like 'ZZ-%';
```
